\section*{Project Context}
\addcontentsline{toc}{section}{Project Context}
The project consists of designing and implementing, within \textbf{INSOMEA}, an
\textbf{end-to-end MLOps platform} that industrializes the life cycle of
\emph{Machine Learning} models. Today, model training, experiment tracking and
deployment rely on manual, poorly reproducible practices: scripts run locally,
results scattered across machines, and hand-crafted production rollouts.

The platform aims to unify this cycle: a user (\emph{data scientist}) uploads their
code and data, triggers an isolated training job on a \textbf{Kubernetes cluster},
and sees its metrics, parameters and artifacts captured automatically in a tracking
server (\textbf{MLflow}). The resulting models can then be registered, versioned,
deployed as inference services and queried, all from a single web interface.

My contribution during this first fortnight covers the \textbf{framing} of the
project, the \textbf{state of the art} of MLOps tooling, and the \textbf{setup of
the technical environment} that underpins all the sprints to come.

\section{Tasks Accomplished}
During this first fortnight, I laid the foundations of the project: framing the
requirements, benchmarking the MLOps building blocks, and deploying a complete
development environment that mirrors the target architecture.

\subsection{Framing and scope}
I defined the functional scope of the platform (code upload, cluster-based
training, automatic experiment tracking, model registry, deployment and
prediction) and organized the work into four sprints following the \textbf{Scrum}
methodology. The first sprint, \emph{Foundation}, covers authentication and project
management.

\subsection{MLOps state of the art}
I carried out a comparative study of the \emph{cloud-native} ecosystem components
in order to settle on a coherent, open-source stack: \textbf{MLflow} for experiment
tracking and the model registry, \textbf{KServe} for inference serving on
Kubernetes, \textbf{Kubeflow Pipelines / Argo} for training orchestration,
\textbf{MinIO} as S3-compatible object storage, and \textbf{FastAPI}~/~\textbf{Angular}
for the application.

\subsection{Environment setup}
I provisioned a \textbf{Kubernetes cluster} and deployed the \textbf{MLflow}
tracking server on it (backed by a \textbf{PostgreSQL} database for metadata and by
\textbf{MinIO} for artifacts). I initialized the \textbf{FastAPI} backend skeleton
(asynchronous, SQLAlchemy) and the \textbf{Angular 19} frontend scaffold.

\subsection{Initial design and start of Sprint 1}
I modelled the two founding entities (\texttt{User}, \texttt{Project}), settled on a
microservices architecture, and chose \textbf{stateless JWT} authentication. I
started implementing authentication (sign-up, sign-in, session refresh) with
\texttt{bcrypt} password hashing.

\textbf{Components set up:}
\begin{itemize}[leftmargin=1.4em,itemsep=2pt]
  \item \textbf{Kubernetes cluster}: namespaces, \texttt{kubectl} access, basic ingress.
  \item \textbf{MLflow}: tracking server with a PostgreSQL backend and a MinIO \emph{artifact store}.
  \item \textbf{FastAPI backend}: project structure, configuration, asynchronous database connection, authentication endpoints (JWT).
  \item \textbf{Angular 19 frontend}: \emph{scaffolding}, routing, sign-in/sign-up screens, \texttt{AuthService} and a \emph{route guard}.
  \item \textbf{Git repository} and a basic continuous-integration pipeline (GitHub Actions).
\end{itemize}

This phase allowed me to consolidate an overall vision of \textbf{MLOps
engineering} and of setting up a \emph{cloud-native} environment.
\begin{itemize}[leftmargin=1.4em,itemsep=2pt]
  \item \textbf{Containerization \& orchestration}: Docker, Kubernetes (deployments, services, namespaces).
  \item \textbf{MLOps ecosystem}: MLflow (tracking \& registry), MinIO (S3 object storage), PostgreSQL.
  \item \textbf{Backend}: asynchronous FastAPI, SQLAlchemy, OAuth2/JWT security, bcrypt hashing.
  \item \textbf{Frontend}: Angular 19 (\emph{standalone} components), Tailwind CSS, session management.
  \item \textbf{Methodology}: Scrum organization, breakdown into sprints and backlog.
\end{itemize}

% --- 4. difficulties ---------------------------------------------------------
\section{Difficulties and Solutions}
\begin{itemize}[leftmargin=1.4em,itemsep=3pt]
  \item \textbf{Access to the cluster's internal services} (MLflow, MinIO) from
        outside: solved by setting up \emph{ingress} and \texttt{port-forward},
        together with dedicated environment variables.
  \item \textbf{MLflow~$\leftrightarrow$~MinIO integration} (artifacts on S3
        storage): solved by configuring the S3 \emph{credentials} and the MinIO
        \emph{endpoint} on the tracking server side.
  \item \textbf{Stateless authentication}: chose an \emph{access}/\emph{refresh}
        token pair and set up an Angular interceptor for transparent session
        refresh.
  \item \textbf{Environment reproducibility}: versioned Kubernetes manifests and a
        \texttt{docker-compose} setup for local execution.
\end{itemize}
