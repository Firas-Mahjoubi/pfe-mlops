\section*{Introduction}
This chapter specifies what the platform must do and how the work was organized.
It identifies the actors, the functional and non-functional requirements, the
global use-case model, the product backlog and its breakdown into four sprints,
and finally the global system architecture that the sprints incrementally build.

\section{Requirements Specification}
\label{sec:requirements}

\subsection{Identification of Actors}
\begin{itemize}[leftmargin=1.4em]
  \item \textbf{Platform user (data scientist).} The primary actor. Authenticates,
        manages projects, uploads code and data, triggers training runs, inspects
        experiments, registers and promotes models, deploys them, and queries
        predictions.
  \item \textbf{External API client.} A third-party application or script that
        calls a deployed model's public endpoint using an \gls{api} key, without a
        platform account.
  \item \textbf{Administrator.} A privileged user who oversees the whole
        platform: manages user accounts (activate, deactivate, promote, delete),
        views platform-wide statistics and cluster health, and inspects every
        user's projects, pipelines, and deployments.
  \item \textbf{System (automated actors).} The training pipeline and the model
        server act on the user's behalf once triggered.
\end{itemize}

\subsection{Functional Requirements}
\begin{itemize}[leftmargin=1.4em]
  \item \textbf{Authentication.} Sign up, sign in, and session refresh using
        \gls{jwt} tokens.
  \item \textbf{Project management.} Create, list, update, and delete projects;
        each project is bound to its own experiment-tracking namespace.
  \item \textbf{Upload.} Upload code (\texttt{.py}, \texttt{.ipynb}, \texttt{.zip})
        and datasets (\texttt{.csv}) through the browser.
  \item \textbf{Training.} Trigger a training pipeline that executes the uploaded
        code on the cluster.
  \item \textbf{Experiment tracking.} Automatically capture metrics, parameters,
        and artifacts; browse and compare runs.
  \item \textbf{Model registry.} Register model versions and promote them between
        Staging, Production, and Archived stages.
  \item \textbf{Deployment.} Deploy a registered model as a live prediction
        service.
  \item \textbf{Prediction.} Send sample inputs and receive predictions, both from
        the \gls{ui} and from a public \gls{api} endpoint secured by per-deployment
        keys.
  \item \textbf{Monitoring.} View live cluster and per-pod resource metrics on a
        dashboard.
  \item \textbf{Administration.} Manage user accounts and roles, view
        platform-wide statistics and cluster health, and oversee all users'
        projects, pipelines, and deployments (administrator only).
\end{itemize}

\subsection{Non-Functional Requirements}
\begin{itemize}[leftmargin=1.4em]
  \item \textbf{Security.} Stateless \gls{jwt} authentication; per-deployment
        \gls{api} keys stored as hashes; ownership checks on every resource.
  \item \textbf{Performance.} Asynchronous backend for I/O-bound concurrency.
  \item \textbf{Scalability.} Each training job and each model server runs in its
        own resource-limited pod on Kubernetes.
  \item \textbf{Portability.} Containerized; runs identically on local KinD and on
        \gls{aks}.
  \item \textbf{Reproducibility.} Isolated execution and automatic recording of
        run inputs and outputs.
  \item \textbf{Usability.} A single, coherent web interface for the whole
        lifecycle.
\end{itemize}

\section{Release Plan and Sprint Breakdown}
\label{sec:release-plan}
The backlog was delivered over four sprints, each producing a demonstrable
increment:

\begin{itemize}[leftmargin=1.4em]
  \item \textbf{Sprint~1, Foundation:} authentication and project management
        (stories 1--2).
  \item \textbf{Sprint~2, Training \& Tracking:} upload, training pipeline, live
        logs, and experiment tracking (stories 3--7).
  \item \textbf{Sprint~3, Registry \& Deployment:} model registry, promotion,
        deployment, and prediction (stories 8--11).
  \item \textbf{Sprint~4, Observability \& Public Serving:} metrics dashboard,
        public \gls{api} keys, and diagnostics/robustness (stories 12--14).
\end{itemize}

\section{Global System Architecture}
\label{sec:architecture}
The platform follows a layered, containerized architecture deployed on Kubernetes.
A browser-based \gls{spa} talks to an asynchronous backend, which orchestrates the
training pipeline, the experiment tracker, the object store, the database, and the
model servers. Public traffic reaches the cluster through a Cloudflare Tunnel.
