\section{Implementation}

\subsection{Authentication with JWT}
Authentication is stateless and based on \gls{jwt}. On login, the backend verifies
the password against its stored hash and issues a short-lived \emph{access} token
and a longer-lived \emph{refresh} token. Protected endpoints depend on a function
that decodes the access token and resolves the current user; the refresh endpoint
exchanges a valid refresh token for a new access token without re-entering
credentials. Passwords are never stored in clear text, only a salted hash is
persisted.

\begin{lstlisting}[language=Python,caption={Resolving the current user from a JWT (backend dependency).},label={lst:get-current-user}]
async def get_current_user(token: str = Depends(oauth2_scheme),
                           db: AsyncSession = Depends(get_db)) -> User:
    payload = decode_access_token(token)        # raises 401 if invalid/expired
    user = await db.get(User, payload["sub"])
    if user is None:
        raise HTTPException(status_code=401, detail="Invalid credentials")
    return user
\end{lstlisting}

\subsection{Project Management}
A project is the organizing unit of the platform. Creating one also provisions a
dedicated experiment in the tracking server, so that every run under the project
is grouped automatically. All project endpoints enforce an ownership check: a user
can only see and modify their own projects. The check deliberately answers
\texttt{404} rather than \texttt{403} for foreign resources, so the existence of
another user's project is not even revealed.

\subsection{Route Protection in the Frontend}
The frontend mirrors the backend's protection with an Angular route guard: any
route under the dashboard requires a valid session, otherwise the router
redirects to the login page. The guard reads the authentication state from a
central \texttt{AuthService}, which also transparently refreshes expired access
tokens.

\begin{lstlisting}[caption={Angular route guard protecting the dashboard routes.},label={lst:auth-guard}]
export const authGuard: CanActivateFn = () => {
  const auth = inject(AuthService);
  const router = inject(Router);
  return auth.isAuthenticated()
    ? true
    : router.createUrlTree(['/login']);
};
\end{lstlisting}

\noindent\textbf{Retrospective.}
What went well: the authentication and project foundations were delivered on
schedule, and settling the token-refresh mechanism early meant no later sprint
had to revisit session handling. To improve: too much of the first week went into
environment setup rather than stories; the lesson, applied from Sprint~2 onward,
was to keep a running development cluster and seed data ready before the sprint
starts.

\section*{Conclusion}
Sprint~1 delivered the security and project foundations of the platform. The next
sprint builds on them to upload, run, and track training jobs on the cluster.
