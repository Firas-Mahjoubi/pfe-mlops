\section{Implementation}

\subsection{Upload and Storage}
Uploaded files are stored in the object store under a key derived from the project
and a short unique prefix. The backend supports plain scripts, notebooks, and
archives, and can auto-detect the entry script when one is not specified,
following a fixed priority order: an explicit user choice always wins, then
conventional names such as \texttt{main.py} or \texttt{train.py}, then the only
script present, and finally the notebook if nothing else qualifies.

\begin{lstlisting}[language=Python,caption={Entry-script auto-detection follows a fixed priority order.},label={lst:entrypoint}]
def detect_entry_script(files: list[str]) -> str | None:
    scripts = [f for f in files if f.endswith(".py")]
    for preferred in ("main.py", "train.py", "app.py"):
        if preferred in scripts:
            return preferred
    if len(scripts) == 1:
        return scripts[0]
    notebooks = [f for f in files if f.endswith(".ipynb")]
    return notebooks[0] if notebooks else None
\end{lstlisting}

\subsection{The Training Pipeline}
A training run is expressed as a small pipeline that executes inside an isolated
pod: it downloads the code (and dataset) from the object store, installs any
missing dependencies, and runs the entry script. Notebooks are first converted to
a Python script. The script is not run directly, it is wrapped by a generated
runner that enables automatic experiment tracking before handing control to the
user's code.

\begin{lstlisting}[language=Python,caption={The generated runner enables autologging before running the user's script.},label={lst:runner}]
import os, runpy, mlflow
mlflow.set_tracking_uri(os.environ["MLFLOW_TRACKING_URI"])
mlflow.set_experiment(experiment_id=os.environ["MLFLOW_EXPERIMENT_ID"])
mlflow.autolog(log_models=True)          # one line instruments sklearn/XGBoost/...
runpy.run_path("user_script.py", run_name="__main__")
\end{lstlisting}

\subsection{Robust Notebook Handling}
Because real-world notebooks are rarely written for headless execution, the
runner includes several robustness measures. Notebooks are converted to scripts
with \texttt{nbconvert}~\cite{nbconvert_docs}; during conversion the runner
strips interactive notebook magics, neutralizes blocking calls such as
\texttt{plt.show()} and \texttt{input()}, and installs compatibility shims for
runtime-only modules (for example \texttt{google.colab}) so that code exported
from cloud notebook environments runs unchanged. Missing imports are detected and
installed inside the pod before execution, with version pins for packages whose
latest releases are known to conflict.

\subsection{Live Logs}
While a run executes, the backend reads the pod's logs from the cluster and streams
them to the interface, so the user watches training progress in real time. The
\texttt{autolog} call records metrics, parameters, and artifacts to the tracking
server with no changes to the user's code.

\noindent\textbf{Retrospective.}
What went well: the autolog wrapper proved the right abstraction, users get full
experiment tracking without changing a line of their code. To improve: the
training and tracking pipeline was the most technically demanding increment, and
handling messy real-world notebooks (runtime-only modules, conflicting
dependency versions) consumed more time than estimated; the diagnostics work
later scheduled in Sprint~4 was a direct consequence of this experience.

\section*{Conclusion}
Sprint~2 turned the platform into a working training-and-tracking engine. The next
sprint makes the resulting models deployable and queryable.
